# 收获概览与隔天继续 — 第一版（2026-10-30）

后续已与界面、图标和生成式对比卡统一集成；当前提交身份、复验结果与合并范围见[多分支集成记录](../../evidence/integration/20261030/README.md)。下文保留首轮实现时的检查基线与试用脚本。

## 本轮范围

以“个人带着一个问题阅读专业材料，探索后保存有出处的理解，隔天回来继续”为验证场景。产品假设是降低找回与重新进入任务的成本；尚未通过用户试验证实。

本轮增加顶栏“收获”视图，使用现有 TreeState / Return / 采用尝试 / 材料列表 / 导航定位接口，无新增数据库表、运行时或模型调用。

- 收获按保存时间倒序，完整正文、保存时间、来源分支和三态采用记录集中呈现。每页 20 条，可继续展开；总数来自全树已保存 Return。
- Turn 来源保留摘录、分支、Turn、entry 和偏移快照，可打开所在轮次并使用既有来源揭示定位。材料来源点击时从数据库导航定位读取 material/version/block，能够在浏览器来源缓存为空时打开原版本与块。
- “继续讨论”显示按最后一条非 Return 消息时间排序的五个分支，打开时保留上次查看轮次。该时间表示讨论活动，不表示用户最近访问，也不判定问题是否解决。
- “继续阅读”复用材料阅读器；阅读器按数据库保存位置选择版本与块，保留已有旧版本、不可读版本与加载失败说明。
- 同一浏览器记住最近打开的 Tree 与每个 Tree×Branch 的轮次 ID。启动对 Tree 列表校验，轮次对当前保存的 Episode/Run/Turn 分组校验；过期 ID 回退现有默认，存储禁用时仍可阅读。仅保存标识，不额外复制正文。这些是浏览器便利游标，材料位置与内容事实仍在数据库；清理浏览器存储或更换浏览器会失去这些便利游标。

保存不等于正确，送入成功运行的上下文不等于模型理解正确。本轮不增加“问题已解决”状态，不自动生成或保存收获，不修改 Return 保存/幂等/采用规则与 session 恢复语义。

## 待执行的两天试用

保持原顺序：Mac 签收后再开展原定 3–5 人独立试用。以下是额外的纵向观察脚本，不替代原 Beta 或长期实验。

第一天：参与者选一份自己确实需要读的论文、技术报告或专业材料，写下一个主问题。允许一句解释与正式支线两种方式；由参与者判断是否值得开支线。参与者编辑并确认 1–3 条收获，逐条指出出处与适用限制，记录第一条有用收获所需时间、帮助次数，以及能否区分“返回主线”和“确认保存”。记录未完成的问题，由研究者保存观察，不自动写成产品状态。

第二天：不给操作提示，请参与者找回指定收获及准确材料版本/段落，记录耗时、误跳与求助；恢复原任务，并观察是否实际复用已保存收获。让参与者用自己的话解释结论与限制，记录哪些内容需要更正。分别记录主动回来和按测试要求回来；可在一周后再次观察。

对照任务可使用普通线性聊天，尽量匹配模型、材料难度、目标与时间，轮换任务顺序。小样本只能发现交互问题和方向信号，不能据此声称市场需求已验证。不要把分支数、Return 数或 deliveredRunId 当作价值证据。

失败检查：浏览器刷新、浏览器存储不可用、来源缓存为空、旧材料版本、session 不可用、保存成功但导航失败、采用尝试失败、材料加载失败。分别记录保存事实、执行能力与体验结果。

## 后续独立增量

1. 普通提问稳定提交键与请求对账；先定义接受、在途、完成但响应丢失的状态及显式重试规则。
2. 长程上下文观测；先展示本次纳入内容与容量，不静默舍弃待采用 Return 或改写恢复语义。
3. 树/分支改名、用户主动请求草稿辅助、易用的带来源导出；分别按真实试用障碍排期。
4. 收获更正/替代/撤回关系需单独签署语义；保留旧记录及采用历史。
