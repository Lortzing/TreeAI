# 普通提问的请求对账（2026-10-30）

在合并后的 `e682af0ca55e6c2db97a6e52f608e9ec0610cd55` 上补齐普通提问的请求身份。产品实现提交为 `6d92d6e124a97e76fcb669f6436c53287f6b846d`；[验证记录](../../evidence/prompt-reconciliation/20261030/README.md)区分产品代码、探针修复、离线机制和未完成的人体验收。

## 行为

- 浏览器在普通提问前生成 `requestKey`，按 Tree×Branch 保留待核对请求。数据库先保存树内唯一键及问题、分支、显式模型和附件组合内容的摘要，再进入异步会话对准与模型调用。Episode、Run 与请求的绑定同事务保存。
- 同键同输入始终读取既有结果：受理、排队、运行、中止中、成功、失败或已中止。同键改问题、分支、模型或附件组合内容产生 409，不重新调用模型。另一 Tree 可以使用相同键。
- 失败、中止和宿主中断都不自动重跑。同一键仍指向原尝试；用户核对终态后再次显式发送，浏览器才生成新键。运行中断沿用既有 Run 恢复规则；对准阶段尚无 Run 的已受理请求也会记为中断失败。
- 网络错误先查请求状态。查不到只表示查询当时没有记录，不能证明先前 POST 永远不会到达；因此保留原键，同一问题再次发送仍使用该键。结果尚不明确时若已改问题、附件或模型，会保留当前编辑并提示先处理原请求，不把新内容绑定到旧键。
- 待核对时发送按钮显示 `↻`，提供“核对上次发送的结果”的名称。即使 Pi 会话文件缺失，也允许纯查询；核对完毕后，普通续聊仍按原规则禁用，显式新探索入口保持独立。
- 对账命中成功后刷新已保存对话；只有当前输入仍与已提交快照一致时才清空。期间新增文字、附件、模型选择或切换 Tree/Branch 都不会被迟到结果清除。

数据库账本只新增身份摘要、Run 关联及对准前失败信息，不复制问题全文。浏览器为重试保存原问题文本、附件引用与显式模型；这与已有客户端 Return 草稿同属本地浏览器存储。浏览器存储不可用时保留同页内存编号，刷新后的恢复能力相应受限；已保存的数据库事实仍然可读。

## HTTP 与存储

`POST /api/trees/:treeId/prompt` 新增可选 `requestKey`。带键返回 `{request,state}`，终态为 200，在途重放为 202；运行失败通过 `request.status/failure` 表达。参数或并发拒绝仍返回原 4xx。旧的不带键接口继续返回原 `{outcome,state}`，内部首问与显式新探索接口也保留原语义。

`GET /api/trees/:treeId/prompt-requests/:requestKey` 返回 `{request,state}`；存在的 Tree 中未找到请求时 `request:null`。请求投影不含 Pi 会话引用、路径、原始错误详情或载荷摘要。

迁移 `0012-prompt-requests` 新增 `prompt_requests`，由原 TreeRepository 连接和事务管理。树/分支及 Run/分支关系受数据库约束。导出、恢复的表全集、复合主键与插入顺序同步包含该表，已验证不随包携带 Pi 会话时仍能读取原结果。

可携带层继续执行原有严格产品 schema 版本校验，没有新增旧包格式迁移能力。版本 11 的旧导出包应先用匹配版本恢复，再升级数据库到版本 12；不要用新版本将旧包校验失败误判为内容丢失。
