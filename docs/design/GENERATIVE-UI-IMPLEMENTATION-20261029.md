# Generative UI 第一版：概念对比卡

日期：2026-10-29。工作区基线：`35ae4a012fd6beea0b66b9bb773dbe858dfedc45`。
本记录对应此基线上的工作区改动，尚不是提交后或发布验收。

## 已实现的体验

在支线的已有模型回答下展开“对比一下”，先查看本次生成来源，可填写不超过 400 字符的比较要求，再显式生成。模型只输出固定结构的 2–3 个概念、1–6 个比较维度。模型推断和附来源内容分别标注，引用可以展开原摘录、核验后定位。

用户可以放大阅读、查看文本视图、勾选收获，随后追加到当前支线的 Return 草稿。放大阅读移动同一个 DOM 节点，勾选状态不丢失；原回答的正文和 UTF-16 偏移不变。写入草稿不提交 Return、不导航，也不改变主会话或采用状态。已有草稿保持，失败请求的草稿在编辑时使用新幂等键。

重新生成产生新版本，已选择的旧版本不会自动替换。成功卡片、失败状态、来源快照和额度都写入 TreeAI DB，刷新或重启后直接读取。Pi session 缺失不影响已保存卡片。来源文本变化时定位失败并说明原因，旧卡片和摘录保留。

Echo 模式展示明确标注的离线样例，**不分析输入资料、不代表模型质量**。Pi 模式使用当前 Studio 选中的 provider/model、同一受控凭据配置，创建独立辅助 runtime、workspace 和 session 目录，工具保持默认拒绝。

## 技术边界

| 层 | 交付 |
| --- | --- |
| 契约 | SDK 无关 `ComparisonDocument` / `UiSourceBinding` / `UiGenerationTask`；`schemaVersion: 1`、`catalogVersion: comparison-v1` |
| 校验 | 精确字段白名单、类型/长度/行列/键唯一性、引用合法性、所有概念逐行齐全、总输出 12,000 字符上限；文本通过 `textContent` 呈现 |
| 来源 | s1 是当前回答的完整文本或显式披露的前 10,000 UTF-16 单元；s2 是支线原选区；保留 Turn hash 或 Material/version/block/range/hash 身份；不从模型接收偏移 |
| 任务 | Tree 范围 intent 唯一；queued/running/succeeded/failed/cancelled/interrupted；全局最多 4 个在途任务，串行执行 |
| 费用控制 | 预留输入与输出字符额度；成功按可见输入输出字符记账；派发后取消、未知结果保留预留并标注未知。它不是供应商 token 或账单金额的精确计量 |
| 超时与取消 | 默认 90 秒，涵盖初始化与 prompt；迟到结果不能覆盖终态；尚未停止的底层操作阻止新派发；重启不会自动重发中断任务 |
| 浏览器 | 原生 DOM + 固定比较表；局部渲染；显式展开才加载；进行中的任务每秒读取状态，关闭/离开/销毁后停止轮询；迟到请求校验当前 Tree/Branch |
| HTTP | 仅本机 Host、同源 Origin、写请求要求 `x-treeai-generative-ui: 1`；服务端检查 Tree、Branch、锚点及来源归属 |
| 持久化 | migration 0011：`generative_ui_tasks`；沿用 TreeRepository 的同一连接、事务与恢复生命周期 |
| 导出恢复 | 新表进入 facts、FK/形状校验与恢复事务；可读 Markdown 包含卡片正文和来源身份；额外接受 schema 10 的原有包，迁移为空卡片表；更旧/未知格式仍拒绝 |

没有新增依赖，Node/npm、锁文件和五个核心包的 SDK 边界保持原有约定。

## 使用与配置

按既有方式启动 Studio。在任意已有支线回答下展开“对比一下”。本地离线示例：

```sh
npm ci
node apps/studio/src/index.ts --driver echo --data /tmp/treeai-comparison-demo --port 8787
```

正式生成需要按 Studio 原有模型设置配置真实 API，并在设置要求时重启；模型调用使用现有 Pi 接入。首次生成前可以展开“本次生成来源”核对发送范围。

`TREEAI_COMPARISON_DAILY_CHARS` 控制每日字符额度，默认 `250000`，以 UTC 日归档。设为 `0` 可阻止新生成，已保存卡片仍可读。该配置是辅助生成的输入/可见输出字符护栏，不能代替供应商的余额或费用上限。

## 与调研提案的差异

- 第一版固定使用 ComparisonCard；练习、自测、模拟、多材料综合和按问题自动选组件仍属于后续阶段。
- 用短轮询读取持久任务状态，尚未增加新的 SSE 事件种类；不解析和渲染半截 JSON。
- 引用范围仅为当前回答与支线原选区，不追加邻近材料块；显示所有维度，首版没有维度筛选器。
- 选择状态保存在当前页面实例；刷新恢复卡片与版本内容，Return 草稿按既有机制保存在当前浏览器。
- 只接受已知版本的服务端契约；未来扩展 catalog/schema 仍需要显式迁移与兼容验证。

专项测试位于 `apps/studio/tests/generative-ui*.test.ts`。覆盖 schema/恶意文本、实例隔离、来源/材料版本、同键重放、预算、取消/超时/迟到、初始化卡死、重启恢复、导出旧包兼容/恶意包拒绝、HTTP、前端晚到响应、放大阅读与 Return 草稿。

完整类型检查、根测试和资源审计的最终结果记录于 [验收状态](../acceptance/status.md)。安装包源目录递归复制包含新增模块；静态 HTTP ESM/CSS 清单已更新并通过审计。原有迁移测试更新至 schema 11，CSS 清单加入新模块；原有测试断言、冻结数据、评估分母和历史证据没有移除。

实际 IAB 浏览器使用临时合成数据验证了：生成前预览、显式生成、表格/文本视图、来源跳转、勾选与草稿追加、刷新恢复、强制停止进程后重启读取、放大阅读与本地勾选。浏览器未记录前端 error；生成额度在读取/刷新/重启后保持 1,597，保存任务仍只有一条。

本轮没有真实 Pi 模型质量结论：当前进程无 API key 环境变量，当前工作区和安装默认数据目录均未配置 `api-settings.json`。无需为工程验证读取用户其他工作区的数据或凭据。下一步质量验收应在配置模型后，用调研文档提出的 20 个真实学习任务评估引用正确性、概念可比性和学习收益；不能把 Echo 或 schema 通过率当作这些结论。

原有 D1 显式 live repro、跨平台实机安装、质量评估与用户试用仍是独立门禁。本次首版工程完成不代表整个 TreeAI 产品验收关闭。
