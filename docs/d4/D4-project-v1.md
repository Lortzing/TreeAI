## 1. 产品目标与完整体验

**让用户带着自己的材料进入 TreeAI，围绕一个问题阅读、探索、形成收获；隔天回来能找到原文、旧探索与收获，并继续思考。**

D3 解决对话中的抽枝与回程；D4 将同一能力延伸到真实材料和持续使用。Tree 仍是一条思考主线，材料服务于目标，不把文件目录变成产品中心。

必须完成的用户路径：

1. 创建或打开 Tree，导入一份 Markdown 或可提取文本的 PDF。
2. 阅读材料，选中原文片段，用自己的问题创建 Branch。
3. 与真实 Pi 连续追问，回到准确原文与阅读位置。
4. 显式确认 Return，将收获带回所属 Tree 的主线；后续主线讨论可追溯其采用记录和材料出处。
5. 关闭、重启后继续；通过搜索找到旧材料片段、已保存批注或 Return，打开其来源并恢复探索。
6. 导出本地数据，在空数据目录恢复；即使 Pi session 不可用，仍能阅读内容、查看出处，并显式开启新的探索。

成功标准是这条路径真实可用、来源可信、用户劳动可保存。D4 不是一个工作日的代称，不承诺未经验证的工期。

## 3. 必须遵守的产品语义

### 3.1 材料与版本

- 一棵 Tree 可关联多份材料；同一材料可显式关联不同 Tree，讨论、Return 与运行记录按 Tree 隔离。
- 保存用户导入的原始文件与不可变版本；版本具有内容 hash、解析器版本、导入时间、解析结果与状态。文件名不是身份。
- 同一材料重复导入相同字节应复用版本；内容变化创建新版本，不覆盖旧摘录、批注和 Branch 来源。不同内容同名文件不得错误去重。
- 首版只支持本地用户显式选择的文件。导入和索引在本地完成，不自动调用模型，也不自动把整份材料发送给模型。
- 搜索、解释、运行中使用哪个版本必须可辨认。切换到新版本不迁移旧锚点到相似文字。

### 3.2 锚点与材料阅读

来源契约扩展为可区分的来源类型：既有 Turn 来源与 MaterialVersion 来源。两者共享验证纪律，但材料不伪造 assistant Turn 或 Pi entry。

材料来源至少包含：materialId、versionId、block/page 标识、规范文本内 UTF-16 半开区间、原摘录与 sourceHash；PDF 页面文字映射由解析器产生，模型不计算坐标或偏移。

- Markdown 渲染必须保留到规范文本的映射；代码块、重复词、跨行、emoji、组合字符均需测试。链接、HTML 清洗不能改变已保存锚点身份。
- PDF 展示真实页面与可选择文字层；选区至少支持同页多个文本片段。跨页选区首版明确提示分段选择，不悄悄截断。
- PDF 文本顺序混乱或字符映射无法验证时，拒绝精确建枝并说明原因；扫描/加密/损坏/超限材料有明确状态。不得将不支持伪装为成功空文档。
- 来源可定位、旧版本可读与 Pi 可续聊分别判断。session 缺失不阻止原文揭示；来源已变更时仍可阅读旧快照。
- 原文阅读与分支探索各自保留位置；回程不要求提交 Return。

### 3.3 从材料建枝及上下文边界

- 材料选文、术语入口和原回答选区最终使用同一 Branch/Origin/Run/Return 服务底层；仅来源解析和初始上下文构造不同。
- 材料没有天然 Pi 分叉点。必须显式建立可追溯的运行起点，将选区、必要邻近段落、材料标题/版本和用户问题作为真实输入；不制造假的历史回答。是否复用树内有效运行或创建独立 session 由开工 ADR 说明并测试。
- UI 在提交前说明本次使用的材料范围；超长上下文有确定上限和截断提示。模型调用走既有受控配置、Run 与 ToolPolicy。
- 保存批注不自动建枝；浏览/搜索不创建 Turn；首问、响应丢失重试、双击与进程重启遵守同一提交意图身份，不能重复派发。
- 同来源可恢复已有探索，也可显式另开；同名词不同材料/版本/Tree 不错误复用。
- 材料 Branch 的 Return 保存到所属 Tree 主线，卡片展示材料标题、版本、页/段、摘录、确认时间及采用记录。没有主线对话锚点时按确认时间放置并提供原文跳转，不伪造一个主线位置。
- Return 保存与导航解耦；保存成功后导航失败不丢收获，失败 Run 的采用尝试与成功采用继续分开记录。

## 5. 搜索、恢复与工程边界

**搜索：** 首版使用本地确定性全文检索。明确支持中文子串/词语和英文词查询；具体索引实现可由研发选择并用固定集验证。默认在当前 Tree，用户可切到全部 Tree；结果说明来源类型、标题、版本、摘录与时间。只索引已保存产品事实，不索引未提交草稿、临时解释缓存或凭据。命中旧版本应标注旧版本。结果跳转后可继续原探索；session 不可用时显示显式新探索入口。索引可从产品数据重建，不能成为唯一事实源。

**导出恢复：** 包含材料原件/版本、产品数据库中的 Tree/Branch/来源/Return/已保存批注和必要版本元信息。默认不含凭据、临时缓存和原始运行日志；如提供包含 Pi session 的选项，必须显式选择并说明敏感内容。缺省恢复只能承诺产品事实可读和可新探索，不承诺旧 Pi 上下文可续。导入先在临时区域验证 schema、校验和、引用完整性与路径，再原子完成；拒绝路径穿越/超限包，失败不覆盖已有数据。首版只要求恢复到空数据目录，不要求自动合并两个已使用数据库。

**安装程序/跨平台：** 本项目将首批支持矩阵明确为 macOS Apple Silicon、Windows 11 x64、Ubuntu 24.04 LTS x64；在D4-0记录具体测试OS/浏览器版本。其他架构不默认为已支持。交付每平台可下载、带版本及校验和的安装产物，普通使用不依赖克隆源码、手动安装Node/npm或编译依赖。可以采用打包本地服务＋系统浏览器，不强制为包装而重写成Electron/Tauri；只有源码启动命令不能完成本项。

安装/首次启动/模型配置/停止/再次启动/版本升级/卸载均有用户可执行流程。默认监听loopback，端口冲突可恢复；平台数据目录、路径分隔符、中文和空格路径、文件权限、文件选择、进程退出/重启与浏览器唤起均测试。升级前保护数据，失败可恢复；卸载默认保留用户资料，清除需显式选择。CI构建产物无凭据，公开下载前给出来源与校验说明；签名/公证状态如实说明，不把缺证书伪称系统签名通过，不要求用户关闭系统安全保护。更新可先提供手动安装新版本，不要求自动更新服务。三平台必须有干净安装实测，Windows原生测试不能以WSL代替；无目标环境标BLOCKED，不以跨平台构建成功替代运行验证。负责人Mac体验判断仍按原人工顺序执行。

**大规模树导航：** 在现有工作台扩展层级导航，支持查找Tree/Branch、折叠展开、定位当前节点、显示完整父路径、直接跳回来源，并在重启后保留必要展开与阅读状态。加载采用分页/按需/虚拟化等适当方式，不能一次渲染全部节点。显示的产品父子关系与运行session树区分，错误来源不得以近似节点替代。长标题、同名节点、100层深链、宽树、空树和失效来源可用；深层路径可收拢但可访问完整路径。键盘可逐层移动与展开，焦点不因虚拟化消失。全局二维Tree Map/无限画布仍非必需，大规模可用的层级导航为必需。

**建议首版支持上限，作为本项目书测试边界：** 单文件 20 MiB；文本 PDF 200 页；单材料解析规范文本 100 万 UTF-16 单元。超限在耗尽资源前明确拒绝。解析任务可取消、迟到结果不挂到已离开的目标，失败不产生“已就绪”材料。

以下为本次制定的目标值，不是已有实测数据。固定 fixture、答案和查询集须在优化前入仓；结果报告分母、环境与失败样例。

| B1 导入/版本 | ≥12 Markdown、≥12 文字层 PDF、≥8 负例；含中文、英文、代码、重复词、emoji、双栏/页眉页脚。有效集全部完成解析；负例全部明确拒绝或降级；重复导入不重复版本，改版保留旧来源 | 服务/存储实测＋真实浏览器 |

## 8. 验收执行与证据格式

保留当前固定 Node 24.21.0 / npm 11.19.0（若升级，单独记录并完整回归）：

```bash
npm ci
npm run typecheck
npm test
npm run verify:d2
node scripts/verify-d2-selftest.js
```

**以下是本项目要求新增的验收入口，目前不是已存在的可执行命令：**

```bash
npm run verify:d4
npm run verify:d4:selftest
npm run run:d4-browser -- --mode selftest
npm run run:d4-browser -- --mode real-pi
```

新脚本帮助文本明确浏览器路径、数据目录与受控 provider/model/agent-dir 参数。真实凭据由环境注入，不写在命令、截图或 Issue。D4 verifier 的离线模式与真实/人工模式显式区分；退出码 0=所选模式全部通过，1=工具错误，2=失败，3=阻塞/未运行。离线绿不等于最终门禁通过；新增 selftest 验证缺证据、坏数据和失败不会被吞成绿色。

每轮交付到 `evidence/d4/`：完整运行 SHA、环境、命令、退出码、fixture hash、逐项结果、脱敏浏览器/模型证据、限制。报告区分本轮执行、仓库记录、代码推断、无法验证；运行与证据提交 SHA 不同时列代码差异及适用边界。允许追加修复证据，不覆盖历史失败记录。

D4-status 表必须含：任务ID、状态、实现代码、被测完整SHA、证据类型、结果、阻断/整改、复验条件。禁止仅写“功能已完成”。
