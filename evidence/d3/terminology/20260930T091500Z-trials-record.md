## Model variance disclosed honestly

An earlier run of the same 60-item set against the same model (working tree,
code identical to the bound SHA, 2026-09-30T09:02Z, report not committed)
measured false-marking at **8/103 = 7.8% (PASS)** with coverage 71/75 = 94.7%
and explain 30/30. The two runs bracket the 10% gate: the false-marking rate
is **borderline-unstable across runs** under the current extract prompt. This
record does not average the two runs and does not claim the gate passed; the
follow-up work is to tighten the extraction prompt/validation (the observed
false marks are ordinary context words the negative lists deliberately
contain: `amplitude`, `pitch`, `noise`, `signal`, `replicas`, `segments`,
`nodes`, `rotation`, `console`, `wavelengths`, `squash`) and re-run at a new
SHA until the gate passes with margin.
